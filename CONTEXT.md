# Trading Journal

Trading Journal is the context for recording, reviewing, and analyzing cryptocurrency futures trading activity.

## Language

**Trading Journal**:
The user's personal record of trades, deposits, targets, plans, screenshots, and reports used to review trading performance.
_Avoid_: Trade Management, Trading Analytics, MyTradeLog

**Trade**:
A lifecycle record of a futures position from entry through final close.
_Avoid_: Fill, Order, Completed Trade

**Close**:
A record that exits part or all of a **Trade** position.
_Avoid_: Exit, Settlement

**Scale-In**:
A record that adds more position size to an existing **Trade**.
_Avoid_: Additional Entry, Entry

**Averaging Down**:
A **Scale-In** made against the current position's price movement.
_Avoid_: scale_in_down

**Pyramiding**:
A **Scale-In** made with the current position's favorable price movement.
_Avoid_: scale_in_up

**Asset**:
The cryptocurrency or trading instrument the user records trades against.
_Avoid_: Symbol, Market

**Supported Asset**:
An **Asset** provided by the application by default.
_Avoid_: Custom Asset, Favorite Asset

**Custom Asset**:
An **Asset** added by the user.
_Avoid_: Supported Asset, Favorite Asset

**Favorite Asset**:
An **Asset** marked by the user for quicker access.
_Avoid_: Custom Asset, Supported Asset

**Exchange Symbol**:
An exchange-specific representation of an **Asset** used for importing or syncing trades.
_Avoid_: Asset

**Position Direction**:
The directional exposure of a **Trade**, either long or short.
_Avoid_: Direction, Side

**Margin**:
The collateral amount allocated to a futures position or part of a position.
_Avoid_: Position Size, Capital

**Position Notional**:
The leveraged market value of a position.
_Avoid_: Margin

**Deposit**:
A user-recorded capital addition used by the **Trading Journal** for performance tracking.
_Avoid_: Exchange Deposit, Funding

**Capital Target**:
A target account value the user tracks in the **Trading Journal**.
_Avoid_: Target, Goal

**Target Price**:
A planned price level in a trading plan for closing part of a future **Trade**.
_Avoid_: Capital Target

**Trading Plan**:
A pre-trade plan that can later be linked to a **Trade**.
_Avoid_: Trade Setup, Strategy

**Report**:
A summary of trading performance and behavior over a **Report Period**.
_Avoid_: Monthly Report as a separate domain, Weekly Report as a separate domain

**AI Report**:
A **Report** generated by an AI model.
_Avoid_: Report

**Report Period**:
The time range a **Report** summarizes, such as daily, weekly, or monthly.
_Avoid_: Period

**User Profile**:
The user's display information and journal settings.
_Avoid_: Account, Trader

**Auth User**:
The authenticated identity that owns a **User Profile**.
_Avoid_: User Profile

**Exchange Connection**:
A user's saved connection settings for importing trades from an exchange.
_Avoid_: Exchange Integration

**Exchange Sync**:
A run that imports trade data through an **Exchange Connection**.
_Avoid_: Exchange Connection

**Imported Trade**:
A **Trade** created from exchange, CSV, or API import data.
_Avoid_: Exchange Sync

**Trade Source**:
The channel through which a **Trade** was created.
_Avoid_: Import Type, Origin

**Import Status**:
The confirmation state of an **Imported Trade**.
_Avoid_: Confirmation Status, Import State

**Initial Capital**:
The starting capital value configured for a **Trading Journal**.
_Avoid_: Capital

**Funded Capital**:
The sum of **Initial Capital** and all **Deposits**.
_Avoid_: Funded, Equity

**Trading PnL**:
The cumulative realized profit and loss from **Trades**.
_Avoid_: PnL, Equity

**Equity**:
The current journal value calculated from **Funded Capital** plus **Trading PnL**.
_Avoid_: Balance, Capital

**Trade Rationale**:
The user's reason for opening a **Trade**.
_Avoid_: Reason

**Trade Review**:
The user's post-trade notes about a **Trade**.
_Avoid_: Notes

**Trade Emotion**:
The user's emotional state recorded for a **Trade**.
_Avoid_: Emotion

**Trade Tag**:
A user-defined classification label attached to a **Trade**.
_Avoid_: Tag

## Architecture language

**Feature Module**:
A vertical slice of the application organized around one product capability.
_Avoid_: Layer Package

**Presentation Layer**:
The feature layer that owns UI components, UI state, and browser interactions.
_Avoid_: Screen Layer

**Domain Layer**:
The feature layer that owns entities, repository interfaces, and use cases.
_Avoid_: Application Layer

**Data Layer**:
The feature layer that owns repository implementations, data sources, DTOs, and external system access.
_Avoid_: Infrastructure Layer

**Core Module**:
Feature-independent shared code used by multiple feature modules.
_Avoid_: Shared Dump, Common Feature

**Composition Root**:
The server-only place where a feature's data implementations are wired to domain use cases.
_Avoid_: DI Module, Factory

**Route Adapter**:
A Next route handler that adapts an HTTP request to a domain use case and maps the result back to an HTTP response.
_Avoid_: API Route, Controller

**Runtime Boundary Suffix**:
A file naming convention that exposes whether a module is server-only, browser-only, or pure shared code.
_Avoid_: File Suffix Rule, Server Client Naming

**Behavior Test**:
A test that verifies observable behavior through a public interface.
_Avoid_: Implementation Test, Structure Test

**Tracer Bullet**:
The first red-green slice that proves a behavior path works end to end.
_Avoid_: Test Batch

**Red-Green-Refactor Cycle**:
The TDD loop of one failing behavior test, the minimum implementation to pass it, and cleanup after green.
_Avoid_: Horizontal Test Batch

**Smoke Test**:
A shallow verification that critical authenticated screens and flows still load after a change.
_Avoid_: Full E2E

## Relationships

- A **Trading Journal** belongs to exactly one **User Profile**.
- An **Auth User** owns exactly one **User Profile**.
- A **Trading Journal** contains zero or more **Trades**.
- A **Trading Journal** contains zero or more **Deposits**.
- A **Trading Journal** contains zero or more **Capital Targets**.
- A **Trading Journal** contains zero or more **Trading Plans**.
- A **Trading Journal** contains zero or more **Reports**.
- A **Trading Journal** contains zero or more **Exchange Connections**.
- A **Trade** is opened on exactly one **Asset**.
- An **Asset** may be a **Supported Asset**, a **Custom Asset**, or a **Favorite Asset**.
- A **Trade** has exactly one **Position Direction**.
- A **Trade** has an initial **Margin**.
- A **Scale-In** adds additional **Margin** to a **Trade**.
- A **Trading Plan** may be linked to zero or one **Trade**.
- A **Trading Plan** contains one or more **Target Prices**.
- A **Report** covers exactly one **Report Period**.
- An **AI Report** is a kind of **Report**.
- An **Exchange Connection** may produce zero or more **Exchange Syncs**.
- An **Exchange Sync** may produce zero or more **Imported Trades**.
- A **Trade** has exactly one **Trade Source**.
- An **Imported Trade** has exactly one **Import Status**.
- **Funded Capital** is calculated from **Initial Capital** plus **Deposits**.
- **Equity** is calculated from **Funded Capital** plus **Trading PnL**.
- A **Trade** may have one **Trade Rationale**.
- A **Trade** may have one **Trade Review**.
- A **Trade** may have one **Trade Emotion**.
- A **Trade** may have zero or more **Trade Tags**.
- A **Feature Module** contains a **Presentation Layer**, **Domain Layer**, and **Data Layer**.
- The **Presentation Layer** depends on the **Domain Layer**.
- The **Domain Layer** does not depend on the **Data Layer**.
- The **Data Layer** implements repository interfaces owned by the **Domain Layer**.
- A **Feature Module** may depend on the **Core Module**.
- The **Core Module** must not depend on any **Feature Module**.
- A **Composition Root** belongs to exactly one **Feature Module**.
- A **Composition Root** wires the **Data Layer** to the **Domain Layer**.
- A **Route Adapter** may call a **Composition Root**.
- A **Route Adapter** must not contain domain rules.
- A **Runtime Boundary Suffix** uses `.server` for server-only modules and `.client` for browser-only modules.
- A **Tracer Bullet** starts a **Red-Green-Refactor Cycle**.
- A **Behavior Test** must use the domain language in this context.
- A **Smoke Test** may use the production demo account only for manual read-oriented verification.
- A **Trade** may contain zero or more **Closes**.
- A **Trade** may contain zero or more **Scale-Ins**.
- A **Close** belongs to exactly one **Trade**.
- A **Scale-In** belongs to exactly one **Trade**.

## Example dialogue

> **Dev:** "Does the **Trading Journal** only store completed trades?"
> **Domain expert:** "No, it includes open trades, deposits, targets, plans, screenshots, and reports."
> **Dev:** "Is a **Trade** one exchange fill?"
> **Domain expert:** "No, a **Trade** is the lifecycle of one futures position, even if it has scale-ins or partial closes."
> **Dev:** "Is a **Close** only the final close?"
> **Domain expert:** "No, a **Close** can exit part or all of the position."
> **Dev:** "Are **Averaging Down** and **Pyramiding** separate records from **Scale-In**?"
> **Domain expert:** "No, they are types of **Scale-In**."
> **Dev:** "Should we call BTCUSDT an **Asset**?"
> **Domain expert:** "No, BTC is the **Asset**; BTCUSDT is an **Exchange Symbol**."
> **Dev:** "Is a **Favorite Asset** the same as a **Custom Asset**?"
> **Domain expert:** "No, **Custom Asset** describes who added it; **Favorite Asset** describes how the user marks it."
> **Dev:** "Is **Position Direction** the same as exchange order side?"
> **Domain expert:** "No, **Position Direction** is the trade exposure: long or short."
> **Dev:** "Can we use **Margin** to mean total account capital?"
> **Domain expert:** "No, **Margin** is collateral allocated to a position; account capital is separate."
> **Dev:** "Is a **Deposit** imported from an exchange wallet event?"
> **Domain expert:** "No, a **Deposit** is a user-recorded capital addition in the journal."
> **Dev:** "Is a **Capital Target** the same as a **Target Price**?"
> **Domain expert:** "No, a **Capital Target** is an account-value goal; a **Target Price** is a planned trade exit price."
> **Dev:** "Is a **Trading Plan** already a **Trade**?"
> **Domain expert:** "No, a **Trading Plan** is a pre-trade plan that may later be linked to a **Trade**."
> **Dev:** "Should weekly and monthly reports be separate domain concepts?"
> **Domain expert:** "No, they are **Reports** with different **Report Periods**."
> **Dev:** "Is an **Auth User** the same thing as a **User Profile**?"
> **Domain expert:** "No, an **Auth User** is the login identity; a **User Profile** stores journal settings and display information."
> **Dev:** "Is an **Exchange Sync** the same as an **Exchange Connection**?"
> **Domain expert:** "No, an **Exchange Connection** stores connection settings; an **Exchange Sync** is one import run."
> **Dev:** "Is `api` a good **Trade Source** name?"
> **Domain expert:** "No, `exchange` is the domain term; `api` is an implementation detail."
> **Dev:** "Is **Equity** the same as **Funded Capital**?"
> **Domain expert:** "No, **Funded Capital** excludes trading results; **Equity** includes **Trading PnL**."
> **Dev:** "Are **Trade Rationale** and **Trade Review** the same note?"
> **Domain expert:** "No, **Trade Rationale** is why the trade was opened; **Trade Review** is the post-trade reflection."

## Flagged ambiguities

- "Deposit" can sound like an exchange wallet event — resolved: **Deposit** means a journal capital addition, not an exchange deposit event.
- "Target" was used for both account goals and planned exit prices — resolved: **Capital Target** means account-value goal, **Target Price** means planned trade exit price.
- "`api` was used as a trade source — resolved: **Trade Source** should use the domain term `exchange` when the source is an exchange import.
